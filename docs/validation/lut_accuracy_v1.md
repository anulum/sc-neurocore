# Measured error of the `lut-v1` transcendental tables

Generated by `tools/lut_accuracy_report.py` from `sc_neurocore.compiler.lut_accuracy`;
`tests/test_lut_accuracy_report.py` fails when this file differs from what the code
measures.

Each cell is the largest absolute error, in real units, of what the generated RTL
returns against the Python model's function clipped to the word's range: first over
inputs inside the table's domain, then over every input the format holds (outside
the domain the table reads its nearest endpoint). Formats up to
18 bits are evaluated at every input code; wider formats are sampled (every
table cell's first and last code, 64 codes inside each cell, 4096 codes on each side
outside the domain). `log`, `sqrt` and `x ** (1/3)` are measured on the inputs the
Python model evaluates (positive, non-negative, non-negative).

`lut-v1` reads the sample point at or below the argument, with no interpolation and
no range reduction, so the error grows with the function's slope and does not shrink
with more fraction bits. These figures state the current lowering; they are not a
target.
